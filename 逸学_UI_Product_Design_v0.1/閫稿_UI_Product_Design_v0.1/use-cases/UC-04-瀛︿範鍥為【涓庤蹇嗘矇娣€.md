# UC-04｜学习回顾与记忆沉淀

## 场景起点

用户主动想回顾近期学习，确认哪里仍值得关注、哪些认识值得以后继续利用。

## 用户目标

用较低成本把近期真实学习中“未来仍有价值”的内容沉淀下来，而不是生成一篇泛泛总结。

## 回顾首页

默认只展示两类信息：

- **最近学习**：近期 Conversation 的轻量列表；
- **值得继续关注**：当前重要 Learning Memory Item 的摘要。

提供：

- “开始一次复盘”；
- “查看全部” Learning Memory Item。

## 发起复盘

1. 用户进入“本次复盘”；
2. 用户可以直接描述最近学到了什么、哪里还卡着；
3. 用户也可以选择最近 Conversation 作为参考；
4. 两种输入方式可单独使用，不要求都填写；
5. 开始后进入复盘对话。

## 复盘过程

AI 以用户真实输入和用户选择的 Conversation 为依据追问，目标是澄清有未来价值的认识、错误或未解决点，而不是覆盖全部近期学习。

## 候选沉淀

复盘结束后，可以产生 0 到若干条候选内容。每条候选必须独立提供：

```text
编辑 / 忽略 / 保留
```

- **编辑**：用户先修改再决定；
- **忽略**：不沉淀；
- **保留**：确认进入 Learning Memory Item。

若候选对应已有同一学习点，应更新原 Item，而不是重复创建。

## 查看全部

按当前意义区分：

- **当前值得关注**：Active；
- **已形成认识**：Inactive。

这只是当前扫描状态，不表示永久掌握度。

## 禁止行为

- 每次学习结束自动弹复盘；
- 自动保存所有 AI 总结；
- 为了“记录完整”生成大量 Item；
- 把同一学习点反复创建为多个 Item；
- 使用掌握度百分比替代真实内容。
