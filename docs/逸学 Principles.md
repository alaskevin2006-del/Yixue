# 逸学 Principles

本文四条 Principle 分别裁决四类问题：

- 学习方式是否被系统侵入；
- 用户是否为系统承担了过高额外成本；
- 系统判断是否超过证据支持范围；
- 模块之间是否形成了不必要依赖

## 1. 真实学习方式优先于系统完整性

逸学服务于用户原本正在发生的学习，而不是要求用户为了使用逸学改变原有学习方式。

当“获得更完整的数据、形成更完整的产品闭环”与“保持用户原本有效的学习过程”发生冲突时，优先保护真实学习过程。

宁可少覆盖部分学习活动，也不为了让系统更完整，要求用户把完整学习迁移进逸学，或按照逸学预设的流程学习。

## 2. 额外用户成本必须由明确收益偿付

在不改变用户原有学习方式的前提下，任何为了系统而额外要求用户进行的填写、确认、整理、维护或信息补充，都必须带来足够明确的用户收益。但要避免误伤自然产生、低成本获得的信息

当“获得更多信息、更完整状态或更强系统能力”与“增加持续用户负担”发生冲突时，优先控制用户成本。

宁可暂时少获得一些信息，也不为了数据完整性、潜在未来价值或系统智能，要求用户长期承担无法证明收益的额外操作。

## 3. 判断的确定性不得超过证据能够支持的程度

系统对事实和学习状态作出的判断，其确定程度必须与现有证据的强度相匹配。

证据不足时，应保留不确定性，不得把推断表达成已经确认的事实；基于现有证据形成的状态判断，也必须允许被后续新证据修正。

当“给出明确结论”与“忠实表达证据的不确定性”发生冲突时，优先保证判断不超过证据本身能够支持的范围。

## 4. 模块依赖必须由明确价值证明

资料、学习过程、复习、规划等能力可以存在真实关联，也可以交换信息，但模块之间新增依赖必须带来足以覆盖其耦合、维护和流程约束成本的明确价值。

当“形成完整、统一、无缝的系统闭环”与“保持职责清晰、减少不必要依赖”发生冲突时，优先后者。

宁可让不同能力之间存在明确接口和局部断点，也不为了叙事上的完整性，把有关联的功能强制串成固定流程、共享混乱状态或形成不必要耦合。
