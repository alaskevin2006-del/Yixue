# 逸学｜网页重构顺序

目标不是一次改完，而是逐页恢复产品语义和视觉语言。

## Phase 0｜只修全局基础

冻结：

- 页面背景；
- 字体体系；
- 主/辅助色 token；
- 全局导航；
- 通用分隔线；
- 按钮/胶囊状态；
- 基础间距尺度。

本阶段不顺手改具体页面内容。

验收后冻结全局 token。

## Phase 1｜首页

优先原因：首页最能暴露当前“日历 + AI + 现状”三者的产品关系。

目标：

- 日历成为唯一主视觉中心；
- 恢复底部输入与向上展开对话；
- 候选日程投影与“继续调整 / 采用”；
- 恢复“现状”抽屉。

## Phase 2｜学科学习

目标：

- 默认进入学习；
- 去掉常驻历史侧栏；
- 历史对话改抽屉；
- 对话区降噪；
- 现状仍按需出现。

## Phase 3｜学科回顾

目标：

- 回顾首页恢复“最近学习 / 值得继续关注”；
- 补齐主动复盘的完整状态；
- 候选 Learning Memory Item 可独立编辑/忽略/保留；
- 查看全部区分 Active / Inactive。

## Phase 4｜资料库

目标：

- 删除重复标题与学习状态入口；
- 公共资料首页收敛；
- 课程点击进入独立详情；
- 恢复搜索、类型/年份/排序的轻筛选；
- 投稿状态语义统一为“审核中 / 已收录”。

## Phase 5｜学科空间总览与学科资料

目标：

- 学科总览去掉“最近活跃”等自行增加信息；
- 学科入口压缩为轻量结构；
- 私人资料只保留搜索、上传、列表；
- 删除“历史资料”等新增层级。

## Phase 6｜响应式与整体回归

逐页检查普通笔记本和手机：

- 核心任务是否被阻断；
- 抽屉是否合理转为覆盖层；
- 是否因为窄屏重新出现信息墙；
- 全局导航和局部 Tab 是否仍清楚。

## 冻结规则

一个页面只有同时满足以下条件才进入 Frozen：

1. Product/Use Case 语义正确；
2. Page Spec 结构正确；
3. Visual Acceptance 通过；
4. 人工截图验收通过。

冻结后，后续页面开发不得顺手重新设计该页。
